# 数据定义

票号与原始编号均为字符串，保留前导零。称重支持 kg、公斤与 t，统一为 kg，单价为 CNY/kg。
毛重与皮重按票号和版本配对，品类、单价、扣杂率与更正目标必须一致。计价重量=(毛重−皮重)×(1−扣杂率)，先量化到0.001kg，再乘单价，金额四舍五入到0.01CNY。
每票第一版不填写 replaces。后续版本只能替代当前生效版，分支或缺基版整票阻断结算。已支付额为各版本中最大累计已付值，待付=最终应付−累计已付；负待付表示待收回。
同编号同原值仅计一次；同编号不同原值全部隔离。空文件、全空行和仅表头分别报错。原始输入计数包括空行及重复表头，对账会分别解释。

## 承运单（车次）

`sample_data/context.json` 的 `trips` 数组定义车次，字段：

| 字段 | 必填 | 说明 |
|---|---|---|
| `trip_no` | 是 | 车次号，同一批内唯一 |
| `waybill_amount` | 是 | 承运单总额，CNY，保留到分 |
| `manifest` | 是 | 票号清单；可写字符串票号或 `{ticket, declared_weight}`，`declared_weight` 用于未结票分摊 |
| `carrier` / `driver` / `departure_at` | 否 | 承运商、司机、离场时间 |
| `currency` | 否 | 默认 CNY |
| `ticket_freights` | 否 | 承运商逐票分项 `{票号: 金额}`；给出时逐票核对，必须与清单完全一致且合计等于承运单 |

裁决口径：

- 车次清单内的票才可入账；清单外生效票标为 `TRIP_TICKET_MISMATCH`，不摊任何承运费。
- 每票计价重来源：`生效`（已结票生效版 `billable_kg`）、`暂定`（未结票最新版本无扣杂计价重）、`申报`（车次清单 `declared_weight`）。三者皆无即 `未入账`。
- 承运费按计价重分摊；以分为单位、最大余数法，逐票合计必须恰等于承运单。`ticket_freights` 给出时改为逐票核对。
- `balanced` 为合计相符；`sealable` 为合计相符且无阻断项。合计不符或含未入账票时不得封存。
- 封存结果按 `(trip_no, version)` 唯一；同一车次相同结果重复封存返回原版本，不新增承运费。
- 已发布后遇到后补更正：新版本 `supersedes` 旧版本，`adjustments` 记录基准版本、调整行（原/新计价重、补退承运费、货款差额、合计补退）与批次；旧版本 `payments` 原付款证据不变。
- 发布在单个事务内完成，中断回滚，不产生半写版本或丢失记录。

## 归档

归档封存保存逐版证据、逐票承运费、隔离原因和运行摘要，非支付执行系统。`GET /api/export/{run_id}` 的 zip 含 `manifest.json`、`evidence.json`、`freight.json`、`publications.json`。数据使用虚构编号，不连接实际支付渠道。
